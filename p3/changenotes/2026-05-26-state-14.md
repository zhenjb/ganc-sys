# 2026-05-26 — STATE-14 Persistent off-chain state manager

## Bối cảnh

STATE-13 đã chốt LocalBuilder dùng "fresh LocalState per Build call" như
một shortcut MVP. Spec STATE-14 (priority P2) yêu cầu thay shortcut này
bằng một manager persistent giữ pending off-chain state xuyên suốt vòng
đời process — đúng mô hình mô tả ở `zkdex_cosmos_deposit_withdraw_flows`
(deposit step 6 indexer credit, withdraw steps 2-3 debit + nullifier).

P4 hôm nay đã viết sẵn:

- `internal/indexer/deposit_indexer.go` (INT-05): convert chain event
  → `types.DepositRecord` rồi `depositRepository.SaveDeposit`. Chưa
  gọi state manager.
- `internal/service/withdraw_service.go` (INT-06): tạo
  `WithdrawRequest`, lưu vào repo. KHÔNG validate pending balance ở
  request-time.
- `internal/service/batch_service.go` (INT-07/09): build batch bằng
  cách đọc deposit/withdraw từ repo và truyền vào
  `batchBuilder.Build(...)`. Submit fail KHÔNG có rollback path.

STATE-14 cung cấp Go API để P4 wire ba điểm này sau, mà không phải
break test INT-02/INT-07 hiện tại.

## Phạm vi triển khai

STATE-14 ship phần **primitive** (long-lived manager + snapshot type +
constructor để builder seed từ snapshot). **Wiring** vào INT-05/06/09
thuộc về P4 — STATE-14 chỉ giao "Go interface boundary" sẵn sàng.

Lý do giới hạn:

- Spec ghi rõ output là `state.OffchainStateManager with thread-safe
  Apply/Rollback/Snapshot`.
- Sửa INT-05/06/09 trong cùng changeset sẽ rủi ro break INT-02/INT-07
  (hai test này lock literal `"0xrootA"`, `userSecret="mock-user-secret"`,
  `balance=60`).
- P3 không sở hữu indexer/service/handler code → đứng ngoài ranh giới
  package theo phân công.

### Quyết định thiết kế quan trọng

1. **Một mutex duy nhất ở manager level (`m.mu`)** — wrap toàn bộ
   `LocalState` operations. Đơn giản, không có ladder deadlock với
   `LocalState.mu` hay `AccountState.mu` nội bộ. Read path (Snapshot,
   Root, Account) cũng đi qua mu để bảo đảm consistent view; chấp
   nhận write-blocks-reads cho MVP, sẽ swap sang RWMutex nếu profile
   chỉ ra contention.
2. **Snapshot deep-copy hết các map**: `accounts`, `appliedDeposits`,
   `appliedNullifiers`. Bắt buộc vì `LocalState` sau đó mutate cùng
   map gốc (`Credit/Debit` ghi `s.accounts.accounts[key] = acc`). Nếu
   chỉ shallow-copy, subsequent Apply sẽ corrupt snapshot đã trả ra
   cho caller.
3. **Snapshot là value type, fields private**: caller bên ngoài
   package KHÔNG construct được — buộc đi qua `m.Snapshot()`. Tránh
   "ai cũng có thể fake một snapshot" gây nhầm trong rollback. Zero
   value vẫn dùng được (Account/IsDepositApplied/IsNullifierApplied
   trả về default) phục vụ test empty pre-state.
4. **Rollback dùng deep-copy thay vì swap pointer**: snapshot vẫn
   immutable sau rollback → caller có thể rollback nhiều lần với cùng
   snapshot mà không bị aliasing với internal state.
5. **Rollback KHÔNG validate snapshot là tổ tiên hợp lệ**. Trade-off:
   giữ API mỏng, semantic đơn giản. Caller (P4 INT-09) chịu trách
   nhiệm chỉ dùng snapshot do CHÍNH manager này mint. Nếu trộn nhầm
   manager, state sẽ bị thay nhưng không có cảnh báo.
6. **Generation tăng đơn điệu trên mỗi mutation thành công**, kể cả
   Rollback. Hiện chỉ dùng cho debug/log; KHÔNG ép caller match
   generation khi Rollback (giữ rollback đơn giản).
7. **Manager KHÔNG biết về secret/wallet**: caller (P4 INT-06) phải
   tự derive nullifier qua `state.NullifierFor(secret, nonce)` rồi
   truyền vào. Đây là contract giữ STATE-14 không lệ thuộc keystore
   implementation — khi P5 wallet sẵn sàng, chỉ phải sửa P4 INT-06,
   không đụng manager.
8. **`NewLocalStateFromSnapshot` là điểm tích hợp duy nhất giữa
   manager (mutable, long-lived) và `LocalBuilder` (per-batch,
   ephemeral)**. STATE-14 KHÔNG sửa `LocalBuilder` (để giữ
   INT-02/INT-07 xanh). Khi P4 sẵn sàng wire, họ có hai option:
   - **Option A — passthrough**: P4 BatchService gọi
     `state.NewLocalStateFromSnapshot(manager.Snapshot())` để có
     `LocalState` pre-seeded, rồi pass vào một `LocalBuilder` variant
     mới (cần build option).
   - **Option B — manager owns build**: tạo
     `state.OffchainStateManager.PrepareBatch(deps, reqs)` helper
     trả về `BuildInput` đã có snapshot. STATE-14 đã chừa chỗ cho
     option này (`Snapshot.Accounts()`) nhưng chưa implement.

## Việc còn lại (out-of-scope)

- **P4 INT-05 wire**: indexer gọi `manager.ApplyDeposit(record)` sau
  khi save vào repo (hoặc thay luôn repo bằng manager).
- **P4 INT-06 wire**: withdraw service tự derive nullifier, gọi
  `manager.ApplyWithdrawRequest(req, nullifier)` trước khi save.
- **P4 INT-09 wire**: BatchService chụp snapshot trước build, hold
  reference. SubmitBatch fail → `manager.Rollback(snap)`.
- **P4 INT-11 wire**: state endpoint đọc `manager.Account(...)` thay
  vì store deterministic snapshot.
- **LocalBuilder snapshot path**: thêm option `WithSnapshot(snap)` để
  seed `LocalState` từ manager thay vì `NewLocalState()`. Cần phối
  hợp với P4 để tránh double-apply deposit (manager đã credit ở
  INT-05 thì builder không re-apply).
- **State persistence to disk**: hiện manager mất state khi process
  restart. Cần WAL hoặc periodic snapshot file cho production. Spec
  STATE-14 không yêu cầu — bound bởi "long-lived in-process".
