# 2026-05-26 — STATE-13 Batch builder facade

## Bối cảnh

P3 đã có đủ STATE-01..09 (primitives). P4 BatchService (`internal/service/batch_service.go`) đã viết trước contract chờ P3, gồm:

- Gọi `batchBuilder.Build(ctx, batch.BuildInput{...})`
- Đọc field `output.BatchCommitments`
- Map `batch.ErrInsufficientOffchainBalance` ở `internal/handler/batch_handler.go` → HTTP 400 `"insufficient off-chain balance"`
- Test int07 + int02 lock literal `OldStateRoot="0xrootA"`, `userSecret="mock-user-secret"`, `oldBalance=0, newBalance=60, nonce=1`

STATE-13 phải đóng vai trò **Go interface boundary** giữa P3 primitives và P4 wiring đã có sẵn.

### Public API export (theo đúng spec STATE-13)

| Symbol | Kiểu | Mục đích |
|---|---|---|
| `batch.Builder` | interface | Ranh giới P3 ↔ P4. Method `Build(ctx, BuildInput) (BuildOutput, error)` |
| `batch.LocalBuilder` | struct | Implementation in-process, orchestrate STATE-03..09 + commitments |
| `batch.NewLocalBuilder()` | constructor | Trả về `*LocalBuilder`, mỗi process nên giữ 1 instance |
| `batch.BuildInput` | struct | Input từ P4: `OldStateRoot, Deposits[], WithdrawRequests[], AccountSecrets[]` |
| `batch.BuildOutput` | struct | Output: `SettlementUpdate, BatchCommitments, Witness` |
| `batch.AccountSecret` | struct | `{Owner, UserSecret}` — OPTIONAL trong BuildInput |
| `batch.ErrInsufficientOffchainBalance` | sentinel | Map từ `state.ErrInsufficientBalance` |
| `batch.ErrInvalidBuildInput` | sentinel | Sentinel cho structural validation |

### Quyết định thiết kế quan trọng

1. **`ctx context.Context` trong Build signature** — khớp với P4 service hiện có. Hiện chỉ check `ctx.Err()` đầu hàm; chuẩn bị cho STATE-14 (persistent manager) có I/O.
2. **OldStateRoot là echo-only metadata** — KHÔNG so sánh với fresh `LocalState.Root()`. P4 hôm nay hardcode `"0xrootA"`; P1 verifier mới là nơi reconcile cuối cùng với on-chain currentStateRoot.
3. **AccountSecrets OPTIONAL** — owner không có entry sẽ fallback về literal `"mock-user-secret"` (chốt trong Agreements canonical Witness JSON). P4 hiện không truyền secret nên fallback này là thứ giữ pipeline chạy được end-to-end.
4. **Fresh LocalState mỗi Build call** — đúng theo "fresh state per batch" shortcut được STATE-14 mô tả ("Replaces the current 'fresh state per batch' shortcut").
5. **Orchestrate đầy đủ STATE-03..09**:
   - STATE-03: `ApplyDeposit` tuần tự
   - STATE-06: `state.NullifierFor(secret, req.Nonce)` cho mỗi withdraw
   - STATE-07: `state.WithdrawAddressHash(req.Destination)`
   - STATE-05: `ApplyWithdrawal(req, nullifier)` với mapping `ErrInsufficientBalance → ErrInsufficientOffchainBalance`
   - STATE-08: gọi `SettlementUpdateBuilder.Build` để re-validate roots/single-denom/destinationHash binding
   - STATE-09: gọi `WitnessBuilder.Build` để re-validate ZK-04/ZK-05 invariant
   - Commitments: `BuildCommitments(upd)`

### Lý do tách hai sentinel

- `ErrInsufficientOffchainBalance` → HTTP 400 với message thân thiện ("insufficient off-chain balance"). P4 handler đã wire `errors.Is`.
- `ErrInvalidBuildInput` → HTTP 500 (default branch) — lỗi structural mà P4 chưa map riêng (caller gửi sai shape).
- Không leak `state.ErrInsufficientBalance` ra ngoài batch package — test `TestLocalBuilder_Build_InsufficientBalance` assert hành vi này.

## Sự cố trong quá trình triển khai

### Lỗi build cross-package lần đầu

Lần đầu viết facade theo signature `Build(BuildInput)` (không có ctx) và field `Commitments`, build `internal/batch` thành công nhưng `go test ./...` báo 3 lỗi:

```
internal\service\batch_service.go:66:43: too many arguments in call to s.batchBuilder.Build
    have (context.Context, batch.BuildInput)
    want (batch.BuildInput)
internal\service\batch_service.go:75:72: output.BatchCommitments undefined
internal\service\batch_service.go:79:28: output.BatchCommitments undefined
```

**Nguyên nhân**: P4 đã viết stub contract trước. Tôi không grep cross-package trước khi định signature.

**Cách xử lý**: Align P3 facade theo expectation P4 đã chốt — KHÔNG đụng vào P4 (theo chỉ thị của user).

### Lỗi test int02 sau khi align

```
expected witness userSecret=mock-user-secret, got "mvp-mock-secret/cosmos1alice"
```

**Nguyên nhân**: Lần đầu tôi đặt MVP fallback là `"mvp-mock-secret/" + owner` (deterministic per-owner). Nhưng Agreements canonical Witness JSON chốt literal `"mock-user-secret"`.

**Cách xử lý**: Đổi fallback thành constant `mvpMockSecret = "mock-user-secret"`.
