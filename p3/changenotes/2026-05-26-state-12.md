# 2026-05-26 — STATE-12 Failure vectors

## Bối cảnh

STATE-02..11 + STATE-13 đã hoàn thành. Folder `testvectors/alice_100_40/` chỉ chứa **happy path** (Alice deposit 100 → withdraw 40 → balance cuối 60). Plan v2 (bảng P3, badge P1) yêu cầu STATE-12 emit thêm **4 negative vector canonical** để các role downstream test pipeline reject:

- **over-withdraw** — STATE-04 / STATE-05 reject vì balance < amount.
- **wrong root** — chain MsgSubmitBatchProof reject vì `oldStateRoot` lệch `currentStateRoot`.
- **duplicate nullifier** — chain / STATE-05 reject vì nullifier replay (intra-batch hoặc cross-batch).
- **tampered destination** — verifier (P1 recompute hash, hoặc P2 circuit binding ZK-07) reject vì `destinationHash != H(destination)`.

Yêu cầu thiết kế:

1. **Tách hẳn happy path** — consumer không vô tình mix một failure vector vào pipeline xanh.
2. **Schema chung + payload tuỳ case** — mỗi vector mang đủ payload mà role consumer cần (Intent / SettlementUpdate / BatchCommitments / PublicInputs / hash).
3. **Determinism** — SHA-256 từng file vào manifest riêng. Hand-edit phá test ngay.
4. **Cross-manifest invariant** — `HappyPathRoots` trong failure manifest phải khớp `roots` trong happy manifest.

### Quyết định thiết kế quan trọng

1. **Schema share giữa generator và loader.** Khác happy path (mirror struct thủ công giữa `main.go` và `pkg/testvectors/alice.go`), STATE-12 cho generator import struct trực tiếp từ `pkg/testvectors`. Lý do: 4 case mới hết, schema phức tạp hơn (nested SettlementUpdate / BatchCommitments / PublicInputs), drift sẽ rất tốn debug. Không có circular import vì `pkg/testvectors` chỉ phụ thuộc `pkg/types`, không phụ thuộc `internal/batch` hay `internal/state`.

2. **Subfolder + manifest riêng, KHÔNG nhét vào manifest cha.** Lý do:
   - Bump `vectorVersion` độc lập (vd. happy path không đổi nhưng tinker schema failure thì chỉ bump 1 bên).
   - `VerifyManifest` cha đã skip subdirectory (kiểm trong `os.ReadDir` loop) → không cần đụng.
   - `TestManifest_AllFilesCovered` cha vẫn assert đúng 11 file (không bị "thêm" failure vào count).
   - `HappyPathRoots` trong failure manifest cross-link 3 root canonical — `TestFailureManifest_HappyPathRootsMatch` bắt drift giữa 2 manifest.

3. **Embed `FailureMeta` thay vì duplicate field per case.** Mọi vector cùng có `case/title/description/violatedInvariant/mutation/rejection/consumers` — embed giảm 7×4 = 28 field declaration thừa và đảm bảo type-safe access (vector.Case khác string).

4. **`FailureStage*` const cho stage label.** Test cross-role (vd. P4 BatchService) có thể assert `rejection.stage == testvectors.FailureStageBatchLocalBuilder` mà không hard-code string — đổi label trong 1 chỗ.

5. **`OverWithdrawVector.AccountSnapshot` snapshot bằng re-run state.NewLocalState().ApplyDeposit(dep1).** Không dùng `ls.Snapshot()` của happy-path LocalState (đã advance qua rootC) — moment realistic mà P4 BatchService nhận intent của user là post-deposit/pre-withdraw, KHÔNG phải post-withdraw.

6. **`WrongRoot.OldStateRoot = sha256("STATE-12/wrong_root/oldStateRoot")`** — placeholder deterministic, KHÔNG random. Mỗi lần regenerate cho ra cùng giá trị → SHA-256 file ổn định → manifest không drift mỗi run.

7. **`DuplicateNullifierVector` chọn kịch bản intra-batch (2 withdrawal entry trong cùng SettlementUpdate).** Lý do:
   - Cross-batch (chain `nullifierUsed[n]=true`, batch mới reuse) cần state on-chain → vector cross-batch là driver-side test, không phải JSON vector.
   - Intra-batch test được ngay với LocalState (apply 2 lần tuần tự cùng nullifier) hoặc chain dup check.
   - Cùng `Nullifier` field xuất hiện ở cả 2 → 1 vector dùng cho cả 2 kịch bản.

8. **`TamperedDestination` re-derive BatchCommitments + PublicInputs từ tampered settlement.** Vì:
   - `BuildCommitments` không validate `destinationHash == H(destination)` — chỉ stringify từng field.
   - Tampered destination thay đổi `withdrawalsRoot` (vì Destination khác) và `withdrawOutputsRoot` (vì... nó dùng destinationHash, không Destination — nhưng destinationHash giữ nguyên, nên output root KHÔNG đổi).
   - Vector cung cấp PublicInputs nhất quán với tampered settlement để P1 verifier không reject sớm ở validate hex.
   - Test `TestTamperedDestination_HashDoesNotMatchRecompute` recompute `state.WithdrawAddressHash(TamperedDestination)` và assert khác `OriginalDestinationHash` → đó là chính xác điểm mà ZK-07 / verifier on-chain catch.

9. **Test `TestOverWithdraw_RejectedByBatchLocalBuilder`** chứng minh facade P3 (mà P4 BatchService dùng) map đúng sentinel `state.ErrInsufficientBalance` → `batch.ErrInsufficientOffchainBalance`. P4 INT-07 test khi tiêu thụ vector này không phải hash-code error mapping — chỉ assert sentinel.

## Sự cố trong quá trình triển khai

Không có sự cố blocker. Quy trình:

1. Viết `pkg/testvectors/failure_vectors.go` — compile fail lần đầu vì có lỡ giữ `crypto/sha256`/`encoding/hex` import sau khi xoá silent reference (artefact từ design phase) → xoá import block và sentinel `var _ = ...`.
2. Viết generator extension — compile fail lần đầu vì test stub bị paste vào file production (`state.Wireless{}` không tồn tại). Đó là test file, không phải production file → cleanup chỉnh sửa test.
3. `go run ./p3/script-test/gen_state_vectors` build pass + emit 4 file + MANIFEST riêng.
4. Test fail lần đầu vì test stub có placeholder type `state.Wireless` — sửa thành `types.DepositRecord` / `types.WithdrawRequest` cụ thể.
5. `go test ./pkg/testvectors/...` xanh ngay lần thứ hai. `go test ./...` toàn suite xanh.

## Cách dùng

### Regenerate cả happy path + failure vectors

```bash
go run ./p3/script-test/gen_state_vectors
```

### Consume failure vectors từ Go

```go
import "github.com/zhenjb/ganc-sys/pkg/testvectors"

// Cách 1: load toàn bundle + sanity check
b := testvectors.MustLoadFailureBundle()
if err := b.SanityCheck(); err != nil {
    log.Fatal(err)
}

// Cách 2: load từng case
ov, _ := testvectors.LoadOverWithdraw()
ls := state.NewLocalState()
_, _ = ls.ApplyDeposit(canonicalDeposit)
wb := state.NewWithdrawRequestBuilder(ls)
_, err := wb.Build(state.WithdrawIntent{
    Owner: ov.Intent.Owner, Denom: ov.Intent.Denom,
    Amount: ov.Intent.Amount, Destination: ov.Intent.Destination,
})
// PHẢI: errors.Is(err, state.ErrInsufficientBalance)
```

### CI integrity check

```go
m, _ := testvectors.LoadFailureManifest()
if err := testvectors.VerifyFailureManifest(m); err != nil {
    log.Fatal(err)
}
```
