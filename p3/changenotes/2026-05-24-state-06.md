## Hành vi đã chốt

### 1. Hash là SHA-256 với domain tag versioned

ZK-02 chưa lock Poseidon/MiMC cuối cùng. STATE-06 dùng SHA-256 (đã có sẵn trong `pkg/hash`) như placeholder. Cơ chế chuyển hash:

1. Khi ZK-02 lock circuit hash (giả sử Poseidon), thay implementation trong `NullifierFor`.
2. Bump `nullifierDomainTag` từ `"v0"` → `"v1"` trong cùng commit.
3. Chạy `go run ./p3/script-test/gen_state_vectors` để regenerate `nullifier_wd_1.json` + `state_after_withdrawal.json`.
4. Test `TestNullifierFor_CanonicalAliceVector` sẽ fail (giá trị đổi) → cập nhật constant trong test cùng commit.
5. Notify P2/P1/P4 về vector mới.

**Why:** version tag trong domain string khiến mọi proof generate trước-bump không verify được sau-bump, ngăn race condition giữa các role.

### 2. API trả `(string, error)` chứ không panic

Không dùng `MustNullifierFor`. Lý do: input có thể đến trực tiếp từ HTTP body (P4 endpoint `POST /api/withdraw-request`). Panic ở layer hash → 500. Trả error → P4 map sang 400 đẹp.

### 3. Nonce canonicalization

`nonce` được parse qua `parseNonNegativeAmount` (cùng parser STATE-04/05 dùng) rồi `.String()`. Hiệu ứng:

- `"01"` → `"1"` trước khi vào hash.
- `"  1  "` → `"1"` (trim trong parser).
- `"+1"`, `"1.0"`, `"0x1"` → reject.

**Why:** nếu không canonicalize, attacker có thể submit `req.Nonce="01"` với nullifier compute từ `"1"` để bypass idempotency (`appliedNullifiers["nullifier-from-1"]` đã có nhưng STATE-05 không re-derive, nhận trực tiếp nullifier qua tham số). Test `TestNullifierFor_NonceCanonicalization` cover.

### 4. Field separator '|' bắt buộc

Bytes `("a","12")` và `("a1","2")` concat trần thành `"a12"` giống nhau. Domain tag và separator '|' đảm bảo input bytes khác → digest khác. Test `TestNullifierFor_DifferentInputsDifferentOutputs/separator prevents collision` cover.

### 5. Nonce=0 hợp lệ ở STATE-06 nhưng STATE-05 reject

`NullifierFor(secret, "0")` trả nullifier hợp lệ. Đây là quyết định: STATE-06 là **pure hash function**, không biết về account state, không reject nghiệp vụ. STATE-05 sẽ trả `ErrNonceMismatch` cho req với nonce=0 (vì expected = account.Nonce+1 = 1 sau deposit). Tách layer giúp test isolation và tránh circular dependency.

### 6. Không có persistent storage

Function pure — không state, không mutex, không I/O. Caller (P4 endpoint, STATE-05 caller, gen_state_vectors) chịu trách nhiệm cache nếu cần.

### 7. `userSecret` là opaque

Không validate format. Có thể là hex string, base64, plaintext "alice_secret" (như test vector). STATE-06 chỉ cần đảm bảo:

- Non-empty sau trim.
- Bytes được ghi vào hash đúng thứ tự.

ZK-02 / wallet layer sẽ quyết định format thực (likely Poseidon field element). Khi đó bump `v0 → v1`.

## Hạn chế đã biết

1. **Hash placeholder không zk-friendly**: SHA-256 không phải Poseidon. Final defense bắt buộc phải swap. Đã document quy trình bump version (xem mục Hành vi #1).
2. **userSecret in vector là plaintext**: `"alice_secret"` được commit vào `nullifier_wd_1.json`. Chỉ phục vụ test vector — production wallet phải derive từ key.
3. **Không có batch derivation**: nếu trong tương lai có nhiều withdrawal trong một batch, mỗi cái cần call `NullifierFor` riêng. Không có vector hóa (chưa cần thiết cho MVP).
